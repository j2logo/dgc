# Cómo contribuir a DGC

Gracias por tu interés en el *Desarrollo Guiado por Contrapruebas*. DGC es una propuesta abierta y mejora con la experiencia de quien la aplica, pero tiene un responsable y un proceso para evolucionar. Este documento explica cómo participar.

## Cómo se decide

El método tiene un autor y responsable, [Juanjo Lozano Gómez (j2logo)](https://j2logo.com), que es quien decide qué entra en cada versión. Las ideas se debaten en abierto y cualquiera puede proponerlas, pero no se incorporan por votación ni por insistencia: se incorporan cuando mejoran el método y encajan con sus principios.

## Dónde va cada cosa

| Quiero… | Dónde |
|---|---|
| **Proponer una idea, criticar algo o plantear un cambio en el método** | [Discussions](../../discussions), categoría *Ideas* |
| **Contar mi experiencia aplicando DGC** | Una [issue con la plantilla «Lo he probado»](../../issues/new/choose) |
| **Señalar un error concreto o aportar un precedente que no se cita** | Una [issue con la plantilla «Propuesta o crítica»](../../issues/new/choose) |
| **Hacer una pregunta** | [Discussions](../../discussions), categoría *Q&A* |
| **Corregir una errata, un enlace roto o una frase confusa** | Una pull request directamente |

## Pull requests

- **Se aceptan sin discusión previa** las correcciones menores: erratas, enlaces, formato o una redacción más clara que no cambia el significado.
- **Cualquier cambio en el contenido del método** (principios, definiciones, prácticas, nuevas secciones) necesita antes una discusión en la que se haya acordado. Las pull requests que cambien el método sin esa discusión se cerrarán, con un enlace para abrirla.
- Una pull request por cambio, con una descripción de qué cambia y por qué.

## Cómo hacer una buena propuesta

- **Indica la sección** a la que afecta (por ejemplo, §5.4).
- **Explica el problema** antes que la solución: qué falla o qué falta.
- **Aporta experiencia o referencias** si las tienes. Una propuesta basada en un caso real pesa más que una basada en una opinión.
- **Distingue entre principio y práctica.** DGC permite adaptar las prácticas a cada equipo; los principios son lo que hace que el método funcione.

## Reconocimiento

Las ideas, experiencias y correcciones que entren en una versión se reconocen en el [CHANGELOG](CHANGELOG.md), con el nombre o el usuario de quien las aportó, salvo que prefiera no aparecer.

## Licencia de las contribuciones

DGC se publica bajo [CC BY-SA 4.0](LICENSE). Al contribuir aceptas que tu aportación se publique bajo esa misma licencia.

## Normas de convivencia

Se debaten ideas, no personas. Las críticas son bienvenidas cuando son concretas y respetuosas. Los mensajes ofensivos, el spam o la autopromoción sin relación con el método se eliminarán.
